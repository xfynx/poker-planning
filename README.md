# Poker Planning

Planning Poker приложение (React + TypeScript backend + Redis), завернутое в Docker Compose.

## Запуск (dev)

```bash
docker compose --profile dev up --build
```

- Frontend: `http://localhost/` (порт **80**)
- Backend: `http://localhost:3000/health`

Запросы с браузера идут на тот же хост, что и страница; Vite проксирует `/rooms`, `/health` и `/socket.io` в сервис `backend` (`VITE_PROXY_TARGET`). Так работает вход по IP/домену, а не только через `localhost:3000`.

### Smoke test (dev)

- **Создать комнату**: на главной нажать “Создать комнату”, при необходимости включить/выключить “Использовать роли”.
- **Войти в комнату**: открыть 2 вкладки, ввести один и тот же код, разные имена.
  - если роли включены — выбрать разные роли (например, 2×`BE` и 2×`QA`)
- **Проголосовать**: выбрать карточки; до Reveal у всех должны быть только статусы (✓/…).
- **Reveal**: ведущий нажимает Reveal — оценки показываются всем.
  - если роли включены: в “Агрегаты” должны появиться отдельные группы по ролям (например `BE` и `QA`) и средние/медианы по каждой
  - если роли выключены: должен быть один общий агрегат “Все”
- **New round**: ведущий нажимает New round — очищаются голоса, скрытие включается снова.

## Запуск (prod)

```bash
docker compose --profile prod up -d --build
```

- Frontend: `http://localhost/` (порт **80**; nginx отдаёт UI и проксирует API/WebSocket)
- Backend: `http://localhost:3000/health`

### После перезагрузки сервера

Все сервисы используют [`restart: unless-stopped`](https://docs.docker.com/engine/containers/start-containers-automatically/): Docker поднимет ранее работавшие контейнеры после запуска демона. Вручную остановленные контейнеры останутся остановленными. Для применения изменений к существующему развёртыванию выполните команду `up -d --build` выше (простой `restart` конфигурацию не обновит).

На Linux с systemd включите автозапуск самого Docker:

```bash
sudo systemctl enable --now docker
```

Не запускайте профили `dev` и `prod` одновременно: они используют одинаковые порты. Redis сохраняет данные в томе `redis_data` через AOF. Комнаты по-прежнему имеют срок жизни 24 часа после последнего продления активности. `docker compose down` сохраняет том, а `docker compose down -v` удаляет его вместе с комнатами. При первом переходе со старой конфигурации данные текущего Redis автоматически в новый том не переносятся.

### Коды, приглашения и оформление

- Новые коды состоят из трёх слов, например `calm-amber-otter`. Регистр при вводе не важен, старые коды и ссылки поддерживаются. Занятый код никогда не перезаписывается: сервер пробует другой.
- Кнопка копирования доступна сразу после создания комнаты и за столом. На HTTPS используется [Clipboard API](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText), на HTTP — запасной способ. Если браузер блокирует оба, ссылка выделяется для ручного копирования.
- Для каждого месяца настроены фон, рамки, цвет акцентов и небольшой сезонный значок. Месяц определяется по локальному времени устройства; открытая вкладка обновляет тему автоматически. Настройки тем находятся в `frontend/src/ui/season.ts`, стили — в `season.css`.

Проверка backend: `cd backend && npm test`. Проверка сборки интерфейса: `cd frontend && npm run build`.
